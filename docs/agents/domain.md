# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root for domain terminology.
- `docs/adr/` for architecture decisions.

Before exploring, read the glossary and ADRs relevant to the work.
If these files do not exist, proceed silently. Create them through
domain modeling when terms or decisions are resolved.

Use the glossary's vocabulary when naming domain concepts in issues,
proposals, code, and tests. Note real vocabulary gaps for domain modeling.

If a proposal conflicts with an ADR, identify the ADR and explain why
the decision should be reconsidered.
